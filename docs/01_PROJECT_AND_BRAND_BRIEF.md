# The Table — Project and Brand Brief

## Document Purpose

This document is the primary source of truth for the product concept, restaurant identity, target users, product goals, brand direction, scope, and phased technical evolution of **The Table**.

It should be used downstream to prevent the project from drifting into a generic restaurant template or being redesigned unnecessarily when the technology stack evolves.

---

# 1. Project Identity

**Project Name:** The Table  
**Product Type:** Premium contemporary restaurant website  
**Primary Discipline:** Frontend development and UI/UX design  
**Initial Platform:** Responsive web  
**Initial Technical Scope:** Static multi-page frontend  
**Long-Term Direction:** Full-stack restaurant reservation and management platform

---

# 2. Project Vision

The Table is a modern restaurant website designed to turn online visitors into restaurant guests.

Within the first few seconds of arriving on the website, a visitor should be able to understand:

- What The Table is.
- What kind of dining experience it offers.
- What kind of food it serves.
- What the restaurant looks and feels like.
- How to view the menu.
- How to make a reservation.
- Where the restaurant is located.

The website should use strong visual presentation, concise content, clear hierarchy, and intuitive navigation rather than overwhelming visitors with excessive information.

The first major phase focuses primarily on **frontend design and development excellence**.

Backend functionality is intentionally deferred until the frontend experience is properly designed and implemented.

---

# 3. Primary Project Objective

Create a professional restaurant website that demonstrates strong frontend engineering and frontend design ability.

The website must:

- Establish a clear restaurant identity.
- Create an immediate emotional and visual impression.
- Present the menu clearly.
- Showcase the restaurant environment.
- Make reservation actions highly visible.
- Provide essential operational information.
- Be intuitive on desktop, tablet, and mobile.
- Follow accessibility best practices.
- Load efficiently.
- Maintain visual consistency across all pages.
- Be structured so it can evolve into a production restaurant platform.

---

# 4. Frontend Development Objective

This project should demonstrate more than the ability to write HTML and CSS.

It should demonstrate the ability to:

- Analyse product requirements.
- Design information architecture.
- Create user flows.
- Plan page hierarchy.
- Design layouts.
- Establish a design system.
- Build responsive interfaces.
- Build reusable UI patterns.
- Design meaningful interactions.
- Handle accessibility.
- Optimise frontend performance.
- Maintain consistency across a multi-page application.

# 5. Restaurant Concept

The Table is a **premium casual / contemporary dining restaurant** based in Johannesburg, South Africa.

It is not positioned as:

- Fast food.
- A casual café.
- A hotel restaurant.
- A nightclub or lounge.
- An ultra-formal white-tablecloth fine-dining venue.
- A food-delivery-first brand.

It should feel appropriate for:

- Date nights.
- Celebrations.
- Business dinners.
- Family meals.
- Small groups.
- Visitors looking for a high-quality meal in a refined but welcoming environment.

The restaurant should feel sophisticated without becoming inaccessible or cold.

---

# 6. Cuisine Direction

**Contemporary South African seasonal dining**

The cuisine is not limited to traditional South African food. Instead, familiar local ingredients and South African influences are interpreted through a contemporary kitchen with selective international influence.

This gives the project a believable and flexible culinary identity while avoiding generic restaurant menu content.

Working examples include:

- Cape Malay-spiced prawns.
- Charred corn with smoked butter.
- Springbok loin.
- Slow-braised beef short rib.
- Market line fish.
- Wild mushroom risotto.
- Rooibos-poached pear.
- Malva pudding reinterpretation.
- South African wine and cocktail selections.

---

# 7. Price Positioning

The restaurant is premium but believable.

Working price ranges:

- **Starters:** approximately R95–R180.
- **Mains:** approximately R190–R380.
- **Desserts:** approximately R90–R150.
- **Cocktails:** approximately R110–R160.
- **Wine:** variable.

These are working ranges used to create realistic interface content. They are not immutable business prices.

---

# 8. Fictional Location

The Table is based in:

**Rosebank, Johannesburg, South Africa**

A precise fictional street address will be created later.

The address should be checked before final use so that it does not accidentally represent an actual restaurant.

# 9. Core Brand Idea

The central brand concept is the **table itself**.

A table represents:

- Gathering.
- Food.
- Conversation.
- Celebration.
- Hospitality.
- Sharing.
- Connection.

The website should subtly reinforce the idea of people coming together rather than relying only on food photography.

---

# 10. Brand Personality

The Table should feel:

- **Warm** — never sterile.
- **Confident** — it should not need excessive copy or decoration to appear premium.
- **Contemporary** — modern typography, layouts, imagery, and interaction.
- **Human** — hospitality and gathering are central.
- **Refined** — details matter.
- **Calm** — generous whitespace and deliberate composition.
- **Sensory** — photography should evoke food, lighting, texture, sound, and atmosphere.

---

# 11. Brand Character

The final visual identity should communicate:

**Modern · Elegant · Warm · Refined · Premium · Welcoming · Uncomplicated**

Premium quality should come from:

- Typography.
- Spacing.
- Composition.
- Photography.
- Detail.
- Consistency.
- Controlled motion.

It should not come from excessive visual effects.

# 13. Target Users

## 13.1 Primary User — New Visitor

A person discovering The Table for the first time.

Primary questions:

- What kind of restaurant is this?
- What food is served?
- What does it look like?
- Is it appropriate for my occasion?
- What is the approximate price level?
- Where is it?
- When is it open?
- Can I reserve a table?

Primary actions:

- Explore the menu.
- Explore the atmosphere.
- Read about the restaurant.
- Make a reservation.

## 13.2 Secondary User — Returning Customer

A customer who already knows The Table and needs quick access to:

- Menu.
- Reservations.
- Opening hours.
- Contact details.
- Address.
- Directions.

The returning-customer experience should prioritise speed over storytelling.

## 13.3 Additional Users

The experience should also remain usable for:

- Couples.
- Families.
- Groups.
- Business diners.
- Event organisers.
- Tourists.
- Customers using assistive technologies.

---

# 14. Core User Journeys

## Journey A — Discover → Menu → Reservation

Home → understand restaurant → Menu → evaluate dishes and pricing → Reservations.

## Journey B — Discover → Atmosphere → Reservation

Home → Gallery/About → understand experience → Reservations.

## Journey C — Returning Customer → Immediate Action

Home or direct entry → Menu / Reservations / Contact.

## Journey D — Mobile Visitor → Practical Information

Home / Contact → hours / address / phone → call, directions, or reservation.

# 15. Experience Principles

## 15.1 Visual First

Photography should communicate:

- Food quality.
- Atmosphere.
- Interior.
- Service.
- Restaurant personality.

Images should have purpose rather than act as decoration.

## 15.2 Content Restraint

Each page must have a clearly defined purpose.

The website should not try to say everything on every page.

## 15.3 Clear Hierarchy

Every page should communicate:

1. Where the visitor is.
2. What the page is about.
3. What information is most important.
4. What the visitor should consider doing next.

## 15.4 Strong Calls to Action

Primary commercial action:

**Reserve a Table**

Major secondary action:

**View / Explore the Menu**

## 15.5 Premium Without Complexity

Avoid:

- Excessive gradients.
- Excessive animation.
- Decorative noise.
- Overly rounded SaaS-style interface elements.
- Generic card grids.
- UI elements that do not help the user.

## 15.6 Mobile Is a Primary Experience

Mobile must be intentionally designed rather than treated as a scaled-down desktop version.

---

# 16. Homepage Restraint Rule

The homepage is not responsible for telling the entire restaurant story.

The homepage should:

**Introduce, entice, and direct.**

It should answer only:

- What is this place?
- What kind of food does it serve?
- What does it feel like?
- Can I book?
- Where is it?

Dedicated pages carry the depth.

This is a locked project principle:

> **Every page should have one clear job. The homepage should not steal that job from the other pages.**

---

# 17. Page Responsibilities

| Page | Primary Responsibility |
|---|---|
| Home | Introduce The Table and direct the visitor |
| Menu | Present food, categories, descriptions, and pricing |
| About | Explain restaurant identity, story, and culinary philosophy |
| Gallery | Show the visual experience and atmosphere |
| Reservations | Capture booking intent with minimal friction |
| Contact | Help users find, visit, or contact the restaurant |

```text
│   ├── Desserts
│   └── Drinks

```

---

# 19. Global Navigation Decision

Desktop navigation:

**THE TABLE · Menu · About · Gallery · Contact · Reserve**

Locked decisions:

- Do not include a separate **Home** item in the desktop navigation.
- The logo returns to Home.
- Do not include both **Reservations** and a separate **Reserve** CTA.
- The reservation action is represented by the distinct **Reserve** CTA.

- Typography.

Technologies:

- HTML5.
- CSS3.
- JavaScript.

- Mobile overlay navigation.
- Sticky header behaviour.
- Gallery lightbox.
- Form validation.
- Form feedback.
- Controlled animations.

## Version 3 — React

Focus:

- Components.
- Props.
- State.
- Reusable UI.
- Data-driven menu.
- Data-driven gallery.
- Form components.

## Version 4 — TypeScript

Focus:

- Data models.
- Component props.
- Shared interfaces.
- Menu item types.
- Form types.
- Safer frontend architecture.

## Version 5 — Next.js Production Frontend

Focus:

- Routing.
- Image optimisation.
- Metadata.
- SEO.
- Server capabilities.

- Real reservations.
- Customer accounts.

- Admin dashboard.
- Menu management.

Adds:
