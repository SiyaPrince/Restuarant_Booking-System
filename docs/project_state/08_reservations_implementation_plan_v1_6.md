# The Table — Reservations Implementation Plan v1.6

## Objective

Implement the approved reservation-request interface while preserving all previously implemented pages.

## In Scope

- Reservation introduction.
- Semantic form structure.
- Date selection.
- Time selection.
- Party-size selection.
- Full name.
- Email.
- Phone.
- Special requests.
- Booking guidance.
- Responsive form layout.
- Explicit notice that Version 1 does not submit or confirm a real reservation.

## Preserve

- Global CSS architecture.
- Home, Menu, About and Gallery implementations.
- Shared header/footer.
- Version 1 no-JavaScript constraint.
- Contact page stub.

## Deferred

- JavaScript validation.
- Availability logic.
- Backend submission.
- Reservation persistence.
- Confirmation emails.
- Authentication.
- Multi-step booking flow.
